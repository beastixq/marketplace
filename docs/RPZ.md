## Структура РПЗ (Расчётно-Пояснительная Записка)

### Аналитический раздел
1. Анализ предметной области онлайн-маркетплейса
2. Сравнительный анализ аналогов (Ozon, Wildberries, AliExpress)
3. Формализация задачи
4. Описание ролей пользователей приложения
5. Описание данных и структур, ER-диаграмма в нотации Чена
6. Анализ существующих СУБД по модели хранения данных

### Конструкторский раздел
1. Схема (диаграмма) проектируемой БД
2. Доказательство 3НФ для каждой таблицы
3. Описание сущностей и ограничений целостности
4. Описание триггера (схема)
5. Описание хранимой функции (схема)
6. Ролевая модель: роли и их привилегии по объектам

### Технологический раздел
1. Обоснование выбора СУБД (PostgreSQL) и языка (Go)
2. Описание реализованных сущностей и ограничений
3. Реализованная ролевая модель
4. Тестирование хранимой функции (таблица классов эквивалентности)
5. Диаграмма взаимодействия РСУБД с InMemory СУБД (Redis)
6. Описание интерфейса доступа к БД (REST API)

### Исследовательский раздел
**Тема:** Исследование влияния индексов и Redis-кэширования на производительность

**Исследование 1 — индексы PostgreSQL:**
- Инструмент: `EXPLAIN (ANALYZE, BUFFERS)`
- Запросы: поиск по категории, заказы пользователя, отзывы на товар
- Метрика: actual time в миллисекундах, seq scan vs index scan

**Исследование 2 — Redis-кэширование:**
- Инструмент: Go `testing.B` или `hey`
- Нагрузка: повторяющиеся GET `/api/v1/products`, `/api/v1/products/{id}`,
  `/api/v1/categories`, `/api/v1/products/{id}/reviews`
- Метрики: среднее время ответа, P99 latency, кол-во запросов к PostgreSQL,
  доля cache hit/cache miss

### Redis-кэширование для описания в РПЗ

Redis рассматривается как внешний учебный слой производительности. PostgreSQL
остаётся источником истины: все изменения записываются в PostgreSQL, а Redis
ускоряет повторные чтения по схеме Cache-Aside.

В реализации используются читаемые ключи без hash: параметры пагинации,
сортировки и фильтров записываются в каноническую query-string часть ключа.
Например, `products:catalog:limit=12&page=1&sort=asc`. Такой формат проще
обосновать в курсовой работе и проверить вручную через `redis-cli`.

TTL задаётся в конфигурации отдельно для карточек товаров, каталога,
категорий и отзывов. Инвалидация выполняется после успешной фиксации
транзакции PostgreSQL; массовое удаление ключей по префиксу использует `SCAN`,
а не `KEYS`, чтобы не блокировать Redis на большом числе ключей.
