## IDEA-001 Require Product Category On Creation

Status: open
Area: products/categories
Found: 2026-05-13

Observation:
Сейчас при создании продукта категорию задавать необязательно.

Question:
Нужно ли делать хотя бы одну категорию обязательной для публикации товара?

Trade-Offs:
- Обязательная категория улучшает навигацию и качество каталога.
- Необязательная категория упрощает черновое создание товара.
- Если категория станет обязательной, нужно синхронизировать API validation,
  web validation, сервисные правила, тесты и документацию.

## IDEA-002 Централизованный Просмотр Отчётов Allure

Status: deferred by user decision
Area: testing/reporting
Found: 2026-11-18

Observation:
Allure Report 2 CLI открывает один сгенерированный отчёт. Для выбора проектов
и запусков из готового интерфейса можно рассмотреть Allure Docker Service
и Allure Docker Service UI. В UI есть выпадающий список отчётов.

Trade-Offs:
- Готовый интерфейс позволяет выбирать отчёты и разделять серии `full`,
  `integration`, `e2e` и `traffic`, без разработки собственной страницы архива.
- Потребуются два дополнительных контейнера, постоянное хранилище и ограничение
  числа сохраняемых отчётов; перед выбором проверить версии, совместимость
  и сопровождение стороннего проекта.
- Для общего доступа нужен работающий backend: один GitHub Pages его не заменяет.
  Потребуется отдельно определить размещение, доступ из CI и правила публикации
  очищенных данных.

Decision:
Сейчас сохраняем статический Allure Report 2 со штатными переходами через
Trend/History. Docker Service + UI — зона роста, не часть текущей реализации.
Собственную страницу выбора отчётов не разрабатывать. Разделение истории
по типам прогонов, понятные номера/даты и полноценные результаты traffic
остаются согласованным направлением улучшения статических отчётов.
